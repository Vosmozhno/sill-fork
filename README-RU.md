# Sill Viewer: сочетания Command с клавиатуры Windows

Изменённый клиент для подключения с Windows к Mac, на котором запущен Sill.
Основа: [NateHag/Sill-Viewer](https://github.com/NateHag/Sill-Viewer), коммит
`1290a4d2395442baf3a541370f44a555ebd5f3aa`.

В архиве находятся исходники, тесты и сценарий сборки. Готового `.exe` в нём пока нет.
Сборку Windows можно получить через GitHub Actions по инструкции ниже.

## Как работают сочетания

После подключения включите **Mac shortcuts (Ctrl → ⌘)** в верхней части Viewer,
затем щёлкните по изображению Mac.

| На клавиатуре Windows | Действие на Mac |
|---|---|
| Ctrl + Q | ⌘Q — завершить активное приложение |
| Ctrl + W | ⌘W — закрыть окно или вкладку |
| Ctrl + S | ⌘S — сохранить |
| Ctrl + T | ⌘T — новая вкладка, если приложение поддерживает |
| Ctrl + C / X / V | ⌘C / X / V — копировать, вырезать, вставить |
| Ctrl + A / Z | ⌘A / Z — выделить всё, отменить |
| Ctrl + Shift + Z | ⌘⇧Z — повторить действие, если приложение поддерживает |
| Alt | Option ⌥ |

Выбор сохраняется отдельно для каждого компьютера. Для нового компьютера режим выключен:
протокол не сообщает операционную систему достаточно надёжно, поэтому её выбор оставлен пользователю.

Для настоящих сочетаний с Mac Control, например Ctrl+C для остановки команды в Терминале,
выключите **Mac shortcuts**. Для Linux оставьте его выключенным.

**Ctrl + Alt + Shift + F** управляет полноэкранным режимом Viewer. Клавиша Windows
не перехватывается. Системные сочетания Windows, например Alt+Tab, остаются у Windows.
Чтобы изменить режим клавиатуры в полноэкранном режиме, сначала выйдите из него.

## Как получить Windows-приложение

Можно использовать новый репозиторий GitHub или свой fork исходного проекта.
В исходный репозиторий автора ничего загружать не требуется.

1. Распакуйте `Sill-Viewer-Mac-shortcuts-source.zip`.
2. Загрузите содержимое папки `Sill-Viewer-Mac-shortcuts` в свой репозиторий GitHub.
   В корне репозитория должны находиться папка `viewer` и файл
   `.github/workflows/windows-shortcuts.yml`. Сохраните файлы в основной ветке,
   обычно `main`. В fork можно заменить соответствующие файлы из архива.
3. Откройте вкладку **Actions**. Если GitHub предлагает включить workflows для fork,
   включите их. Выберите **Windows with Mac shortcuts → Run workflow → Run workflow**.
4. Дождитесь успешного завершения задач **keyboard** и **windows**. В завершённом запуске
   найдите раздел **Artifacts** и скачайте **SillViewer-windows-mac-shortcuts**.
5. Распакуйте скачанный архив, затем вложенный `SillViewer-windows.zip`.
6. Завершите старый Viewer через значок возле часов → **Quit Sill Viewer**.
   Запустите новый `Sill Viewer.exe` из распакованной папки. Сохраните рядом все `.dll`.
7. Подключитесь к Mac, включите **Mac shortcuts (Ctrl → ⌘)** и щёлкните по изображению.
   Для проверки сначала сохраните открытые документы и попробуйте Ctrl+S или Ctrl+T
   в подходящем приложении. Ctrl+Q завершает приложение на Mac.

Если ранее был установлен автоматический обновлятор из исходного проекта,
держите изменённую сборку в отдельной папке: обновлятор может заменить свою установленную
копию исходной версией.

Сценарий запускается вручную, собирает архив и не публикует релиз.
Порядок ручного запуска описан в [документации GitHub](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow?tool=webui).

## Для работы с исходным репозиторием

`mac-shortcuts.patch` содержит изменения относительно указанного выше коммита.
Его можно применить в корне чистой копии исходного репозитория:

```sh
git apply --check mac-shortcuts.patch
git apply mac-shortcuts.patch
```

Архив уже содержит изменённые файлы; повторно применять патч к ним не нужно.

Проверки клавиатуры из корня репозитория:

```sh
cargo test --locked --manifest-path viewer/tests/keyboard/Cargo.toml
```

Для этих проверок не нужны FFmpeg, работающий Mac или графическое устройство.
Используется настоящий модуль ввода клиента и egui той же версии, что и у Viewer.

## Что проверено

- 17 автоматических тестов прошли: передача Command, Shift и Option, быстрые нажатия,
  копирование/вставка, переключение режима, потеря фокуса, повторные нажатия и локальное
  сочетание полноэкранного режима.
- Всё приложение прошло `cargo check --locked` на macOS ARM64.
- `cargo check --tests --locked` также прошёл; Windows-переключатель включён в тестовую
  конфигурацию, чтобы его код проверялся компилятором и на macOS.
- В исходных `decode.rs` и `wire.rs` остались два предупреждения компилятора.
- Проверены синтаксис YAML сборки и применимость патча.

Windows-сборка через GitHub Actions ещё не запускалась. Работа готового приложения
на реальном Windows-ПК и передача сочетаний на Mac требуют проверки после сборки.
